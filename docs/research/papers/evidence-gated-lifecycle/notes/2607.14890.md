## Boundary conditions and limitations

The transfer is an inference: a receipt identity can prevent stale lifecycle
promotion in swe-term if every relevant verification input is represented and
refreshed. It cannot establish semantic program correctness, replace scoped test
selection, or decide policy. New inputs omitted from the identity remain a
possible stale-evidence failure.

## swe-term transfer

- Observed local failure: a previously passing result can be used after a
  relevant source or verifier input changes.
- Relevant contracts: `VerificationReceipt`, `Obligation`, lifecycle invariant 6,
  and the target state-expansion refactor.
- Smallest transplantable mechanism: pure receipt gate comparing a sealed
  passing receipt identity to the current obligation identity.
- What not to copy: unattended-loop engine, reviewer topology, local-key bundle
  format, self-application corpus, and model-dependent outcome claims.
- New risk: an incomplete identity falsely treats a changed environment as fresh;
  explicit fields and fail-closed validation are required.

## Cheapest falsification

- Hypothesis: exact identity binding prevents false lifecycle promotion when a
  relevant verification input changes.
- Null hypothesis: the identity is insufficient to distinguish stale from current
  evidence, or rejects unchanged scope unpredictably.
- One independent variable: result-only acceptance versus current-identity-bound
  receipt acceptance.
- Fixture set: fresh pass; missing or failed receipt; source, verifier,
  arguments, config, runtime, and lockfile change; tampered body; unchanged
  scope; replay.
- Primary metric: false lifecycle promotions.
- Safety-critical counter: false promotions must be zero for treatment.
- Required access: local Go toolchain only.

## Taste update

The useful part of this paper is not its autonomous-loop outcome. It makes the
causal boundary explicit: a lifecycle must act on independently admissible
evidence, not agent text. This suggests a screening rule for future papers:
prefer designs that reveal the invalidation key and the failure path over designs
that report a successful agent run.
